# 2026-09-18 — Brain in a Jar v1

## 이번 작업의 목표

이전까지 MapleFly는 사람이 키보드로 움직이는 작은 2D 게임이었다.

이번 단계의 목표는 캐릭터의 입력 소스를 다음처럼 바꾸는 것이다.

```text
사람 키보드
   ↓
MapleFly 캐릭터
```

에서

```text
게임이 만든 감각 자극
   ↓
실제 MaleCNS connectome
   ↓
descending neuron 활동
   ↓
MapleFly 행동 버튼
```

으로 교체한다.

## 왜 A 방식으로 갔나

선택지는 두 가지였다.

A. upstream의 고정 commit asset을 브라우저가 직접 읽음  
B. 58MB가 넘는 connectome asset을 MapleFly 저장소 안에 복사

우선 A를 선택했다.

이유:

- 구현 속도가 빠름
- MapleFly 저장소가 불필요하게 커지지 않음
- upstream이 공개한 browser-export 파일을 그대로 사용 가능
- 문제가 생기면 어떤 upstream snapshot인지 commit으로 재현 가능

대신 네트워크와 raw GitHub availability에 의존한다는 단점이 있다.

## 실제로 추가한 코드

### 1. src/brain/fly-worker.js

대형 connectome 계산을 메인 화면과 분리했다.

브라우저 Worker 안에서:

1. upstream의 `brain.json` 읽음
2. `meta.bin` 읽음
3. `weights.0.bin`, `weights.1.bin` 읽음
4. MaleCNS cell type / side index 구성
5. 25M+ 시냅스 구조 파싱
6. 20ms timestep의 LIF network 실행
7. descending/motor group spike rate를 메인 thread로 전달

사용한 update는 upstream browser implementation과 같은 계열이다.

```text
v <- decay*v + gain*(W @ spikes) + tonic + noise + sensory drive
v >= 1 -> spike, reset
```

### 2. src/brain/fly-controller.js

게임과 뇌 사이의 어댑터다.

#### 입력

현재 가장 가까운 살아 있는 버섯을 visual target으로 삼는다.

- LC10a: target이 어느 쪽에 있는지
- LPLC1: 작고 접근하는 대상
- LPLC2: looming
- LC4: 가까운 threat
- SNta: 발 접촉

상단 점프 갭은 아직 photoreceptor/optic-flow 렌더러가 없어서
LPLC2/LC4에 넣는 edge/threat proxy로 처리했다.

이 부분은 "실제 파리가 낭떠러지를 저 뉴런으로 본다"는 주장이 아니라
2D 맵을 현재 connectome 입력 채널로 변환하기 위한 인터페이스다.

#### 출력

- DNa02 L/R 차이 -> 좌/우
- DNp01 -> 점프
- leg extensor/flexor group -> 사다리 위/아래
- arm-pull descending group -> 공격

여기서 공격 매핑은 특히 주의해야 한다.
초파리에 "메이플 버섯 공격 뉴런"이 있는 것이 아니다.
threat에 반응하는 descending output을 게임의 ATTACK 버튼으로 연결한 실험 인터페이스다.

## 왜 direct bot 로직을 넣지 않았나

넣지 않은 것:

```js
if (mushroom.x > player.x) moveRight();
if (nearMushroom) attack();
```

이렇게 하면 connectome을 거칠 이유가 없고 그냥 자동사냥 봇이 된다.

현재 구현은 반드시:

```text
버섯 위치
 -> 감각 뉴런 자극
 -> 166,700 뉴런 / 25M+ 연결
 -> 실제 output group firing
 -> 행동
```

을 거친다.

## 라이선스/출처

browser connectome 파일 형식과 LIF 구현은 MIT License인
`alextitonis/fly.ai`의 browser implementation을 참고해 vanilla JavaScript Worker로 포팅했다.

MapleFly 자체에 upstream 대형 바이너리는 저장하지 않는다.

## 아직 모르는 것

코드를 붙였다고 해서 초파리가 버섯을 잡는다는 뜻은 아니다.

오히려 현재 예상되는 실패:

- DNa02 신호가 약해서 거의 안 움직임
- 랜덤 firing 때문에 엉뚱한 방향으로 움직임
- DNp01이 너무 자주/너무 적게 발화
- 사다리 motor group이 실제 입력에 반응하지 않음
- 공격 output이 실용적인 빈도로 나오지 않음
- 브라우저가 connectome 때문에 느려짐

이것들은 숨겨야 할 버그가 아니라 다음 실험에서 측정해야 할 결과다.
